# Plan primera semana

Este plan está pensado para que el colega programador entre con contexto y empiece a aportar valor rápido.

## Día 1 — Entender el sistema

- Leer `README.md`.
- Leer `docs/vision.md`.
- Leer `docs/workflow.md`.
- Leer `docs/ideal-client.md`.
- Leer `docs/collaboration.md`.
- Revisar `KANBAN.md`.
- Revisar `templates/` y `data/leads-example.csv`.

### Resultado esperado

- Entender qué se quiere vender.
- Entender cómo se detecta un posible cliente.
- Entender dónde falta estructura técnica.

## Día 2 — Auditoría técnica del repo

- Revisar las 3 carpetas de webs actuales.
- Detectar qué partes son demos sueltas y cuáles pueden convertirse en base reutilizable.
- Anotar incoherencias de estructura, estilos, assets o despliegue.
- Escribir propuesta breve de mejoras técnicas.

### Resultado esperado

- Lista clara de problemas del repo actual.
- Lista de piezas reutilizables.

## Día 3 — Propuesta de scaffold v1

- Definir stack sugerido para nuevas demos.
- Proponer estructura mínima de proyecto.
- Proponer convenciones de naming, assets y componentes.
- Definir cómo arrancar una nueva demo en poco tiempo.

### Resultado esperado

- Documento o PR con scaffold base recomendado.

## Día 4 — Sistema de captación más operativo

- Revisar el proceso de leads.
- Proponer mejoras al scoring.
- Proponer formato de ficha de lead más útil.
- Decidir si conviene usar CSV, Notion, Airtable o algo más simple al principio.

### Resultado esperado

- Sistema más claro para priorizar oportunidades.

## Día 5 — Acción útil y cierre de primera iteración

- Elegir una mejora concreta y dejarla hecha.
- Puede ser una de estas:
  - scaffold inicial,
  - plantilla mejorada,
  - estructura de assets,
  - sistema de scoring,
  - mejora de una demo existente.

### Resultado esperado

- Primer aporte real visible en el repo.
- Siguiente paso técnico bien definido.

## Checklist de primera semana

- [ ] Entendí la lógica del proyecto.
- [ ] Revisé toda la documentación.
- [ ] Revisé las webs de ejemplo.
- [ ] Detecté los principales huecos técnicos.
- [ ] Propuse un scaffold reutilizable.
- [ ] Propuse mejoras al sistema de leads.
- [ ] Dejé al menos una mejora aplicada.
